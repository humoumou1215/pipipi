一、Pi 是什么？

Pi 是一个 开源 AI Agent 框架，核心产品是一个在终端中运行的 交互式编码助手 CLI（命令行工具）。你可以把它理解为：

  • 一个能调用系统工具（读文件、写文件、跑命令）的 ChatGPT
  • 自带终端 UI，体验比 curl 调用 API 好很多
  • 支持 30+ 家大模型提供商（OpenAI、Anthropic、Google、DeepSeek…）
  • 可以通过「扩展」和「技能」进行二次开发

这正是我们要学习的地方 —— 因为它是可扩展的，所以值得深入代码去 定制。

二、什么是 Monorepo？（初学者必读）

概念解释

Monorepo = Mono（单一） + Repository（仓库）。意思是把多个逻辑独立的「包（package）」放在同一个 Git 仓库里管理，而不是每个包一个仓库。

Pi 项目采用的是 npm workspaces 方案（在 package.json 中声明）。你可以打开根目录的 package.json#L5-L13 看看：

"workspaces": [
  "packages/*",
  "packages/storage/*",
  "packages/coding-agent/examples/extensions/with-deps",
  ...
]

这告诉 npm：packages/ 下的每个子目录都是一个独立的包，它们之间可以互相引用而不需要发布到 npm。好处：

  • 共享代码方便（pi-coding-agent 直接引用 pi-agent-core 的源码）
  • 统一构建、测试、版本发布
  • 一个 PR 就能改多个包的联动代码

三、项目包架构全景

Pi 的代码分层非常清晰。从 用户输入 到 LLM 返回结果，请求会穿过以下几层：

👤 用户（终端输入）
↓
pi-coding-agent（CLI + TUI 界面层）
↓
pi-agent-core（Agent 运行时 + 工具调用 + 会话）
↓
pi-ai（多 LLM 提供商统一 API 层）
↓
🌐 OpenAI / Anthropic / Google…（真正的 LLM 服务商）

各包职责表

包名目录一句话职责二次开发时的用途
pi-coding-agent packages/coding-agent/ CLI 入口 + 终端 UI + 所有编码工具 ⭐ 添加自定义工具、扩展、技能（主战场）
pi-agent-core packages/agent/ Agent 核心循环、会话存储、记忆压缩 ⭐ 修改 Agent 行为、实现新的记忆策略
pi-ai packages/ai/ 统一调用 30+ 家 LLM Provider ⭐ 接入新的 LLM 提供商、自定义模型配置
pi-tui packages/tui/ 终端 UI 组件库（差异渲染） 改 UI 布局、新的终端组件
pi-protocol packages/protocol/ 进程间通信协议（CBOR 编解码） 扩展 RPC 通信协议时需要
pi-client / pi-server packages/client/ 客户端-服务端 IPC 通信 分布式部署、远程调用时需要
pi-evals packages/evals/ 评估框架，测 Agent 能力 验证你的改动是否提升了效果

包依赖关系（简化版）

coding-agent  →  agent-core  →  ai
                ↓                    ↓
              protocol            providers (30+)
                ↑
            client/server

理解这个依赖图非常重要：

  • 如果改 ai 包，agent-core 和 coding-agent 都会受影响
  • 如果改 coding-agent，其他包不会被动依赖它（它是顶层包）
  • 所以做二次开发时，优先在 coding-agent 层修改 —— 影响面最小

四、开发环境命令总览

根目录 package.json#L14-L49 的 scripts 定义了所有常用命令。你 必须记住以下 4 个：

命令作用什么时候用
npm install --ignore-scripts安装依赖（不执行生命周期脚本，更安全）第一次克隆后
npm run build按顺序构建所有包（tui → ai → agent → …）改代码后、运行前
npm run checkLint + 格式化 + 类型检查（全通过才允许提交）⭐ 每次改完代码必跑
./test.sh跑非 e2e 测试（跳过需要 API Key 的）验证改动没有破坏功能
为什么是 --ignore-scripts？

Pi 对供应链安全非常严格（见根 README 的 "Supply-chain hardening" 章节）。默认禁止运行依赖包的 install 脚本，防止恶意代码执行。

另外两个很有用的脚本：

  • ./pi-test.sh —— 从源码直接运行 pi CLI（开发时最常用），可以在任意目录调用
  • npm run build:offline —— 离线构建，不联网刷新模型数据

五、构建顺序为什么重要？

看根 package.json 里的 build 脚本（第 16-17 行）：

"build": "cd packages/tui && npm run build \
  && cd ../ai && npm run build \
  && cd ../agent && npm run build \
  && cd ../storage/sqlite-node && npm run build \
  && cd ../../protocol && npm run build \
  && cd ../client && npm run build \
  && cd ../coding-agent && npm run build \
  && cd ../server && npm run build"

这是严格按依赖顺序的：被依赖的包先构建。如果跳过顺序直接 build coding-agent，会报错找不到其他包的编译产物（dist/ 目录）。

经验法则：如果构建报错 "找不到模块 @earendil-works/xxx"，99% 的原因是你没有按顺序构建或依赖包还没 build。跑一遍完整的 npm run build 就好。

六、动手练习

🎯 练习 1：验证开发环境

在仓库根目录运行 node --version，确认版本 ≥ 22.19.0（见根 package.json engines 字段）。如果版本不够，先升级 Node。

运行安装依赖：npm install --ignore-scripts

第一次会比较慢（几百个包）。如果已经装过会很快。

尝试运行完整构建：npm run build

观察终端输出，注意看构建顺序。

💡 提示：如果模型数据获取失败，可以先用 npm run build:offline 跳过。

构建成功后，运行类型检查：npm run check

（如果只是 clone 下来没改代码，应该全部通过。）

运行 pi CLI 看看帮助：./pi-test.sh --help

如果能看到帮助文本输出，环境搭建成功！🎉

🎯 练习 2：识别包的入口文件

阅读以下 3 个文件，找出它们的 入口导出（通常是 index.ts 的 export 语句）。不需要理解每个导出的含义，只要：

  1. 找到每个包的 src/index.ts
  2. 数一下有多少个 export 语句
  3. 记录它们在你自己的笔记里（后续课会用到）
  • packages/ai/src/index.ts
  • packages/agent/src/index.ts
  • packages/coding-agent/src/index.ts
