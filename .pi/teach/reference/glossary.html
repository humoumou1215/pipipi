术语表

本课程统一术语。所有课程与参考文档都遵循这里的定义。

LLM provider(提供商)
一家模型服务商(OpenAI、Anthropic、Google…)。在 pi 中,每个 provider 是 packages/ai/src/providers/ 下的一个实现,负责把统一的调用翻译成该厂商的 API 请求。
model(模型)
provider 提供的一个具体模型(gpt-4o、claude-sonnet-4-5…)。pi 里 models.generated.ts 存有所有已知模型的元数据。
agent loop(agent 循环)
agent 的核心循环:把对话发给 LLM → 模型返回文本或工具调用 → 执行工具、把结果放回对话 → 再发给 LLM,直到模型给出最终答复。packages/agent/src/agent-loop.ts 是其实现。
tool calling(工具调用)
LLM 接口允许模型"请求"调用你提供的函数(如读文件、跑命令)。模型不执行,只输出参数;由你的代码执行并把结果送回对话。
streaming(流式)
LLM 逐 token 返回输出,而不是一次性给完整回答。是打字机效果的基础,也是长回答等待时间不被感知的关键。
context(上下文窗口)
一次对话中模型能"看到"的 token 上限。超过就需要压缩(compaction)或丢弃。
extension(扩展)
一段在 pi 运行时加载的代码(一个 TS 文件或一个 npm 包),通过扩展点挂进 coding-agent:自定义工具、命令、提供商、UI、生命周期钩子等。packages/coding-agent/examples/extensions/ 是可运行的示例。
hook / 扩展点
扩展系统留给扩展"挂钩"的位置(如 session_start、model_select、input 事件)。扩展声明自己监听哪些点。
ctx(扩展上下文)
扩展函数收到的上下文对象,提供与 pi 交互的能力:注册工具、读配置、调用 UI(ctx.ui.select() 等)、访问对话状态。
EventStream(事件流)
pi 各层传递异步事件的方式(流式回调),agent loop 的输出、LLM 的流式响应都用它承载。
