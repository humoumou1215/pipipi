地形图:pi 的三层蛋糕

学任何大仓库,第一步都是先看骨架,再看血肉。本课给你一张永不迷路的地图。

本课结束,你能:
  • 说出 pi 的三个核心层,以及每层解决什么问题
  • 在仓库里找到扩展开发的四个关键位置
  • 说出加载一个扩展的两种方式

1 · 为什么先学地图

你的目标是基于 pi 做拓展开发、构建自己的 agent。就像去陌生城市之前先看地图:不需要记住每栋楼,但要分清"市中心在哪、我要去哪个区"。pi-mono 有 9 个包,但你的主战场只有三个核心层,其余是支撑设施。

2 · 知识:三层蛋糕

产品层 · coding-agent
packages/coding-agent
CLI、TUI、会话管理、权限——以及扩展系统。你要写的扩展挂在这里。
依赖 ▲
运行时 · agent
packages/agent
agent 循环:反复把对话发给 LLM,执行工具,直到任务完成。
依赖 ▲
统一接口 · ai
packages/ai
一套 API 调用几十家 LLM 提供商:流式、工具调用、图像模型。

调用方向是从上往下:product 层用 agent 层,agent 层用 ai 层,ai 层用各家厂商的 HTTP API。另有一些旁支包:packages/tui(终端 UI 库)、packages/protocol/client/server(RPC)、packages/storage(持久化)——它们支撑产品层,但不是扩展开发的主战场。仓库 README 的包表格是最权威的概览。

关键洞察

你的扩展站在 coding-agent 的扩展系统上,通过它调用 agent 和 ai 的能力。所以学习路线很自然:先看地图(本课)→ 补 TypeScript 阅读能力 → 补 LLM 概念 → 读 ai 层 → 读 agent 层 → 写扩展。一步一个台阶。

不懂的术语(provider、agent loop、tool calling、streaming、ctx…)先不用背,术语表已经备好,随查随用。

3 · 技能:仓库寻宝

下面 4 个任务,先自己找,再揭晓。用 ls、find、rg 都行。找对位置的回报是:以后你写扩展时,知道去哪里抄模板、查文档。

任务 1

找出"所有 LLM 提供商实现"所在的文件夹。
提示:里面应有 anthropic.ts、openai.ts、google.ts 这样的文件。

揭晓答案

packages/ai/src/providers/

为什么重要:将来你要接入自己的模型厂商(自定义 provider),就是照着这些文件的模式写一个 xxx.ts。扩展示例里有一个现成的 custom-provider-anthropic/ 可以参考。

任务 2

找出"agent 循环"的实现文件。
提示:在 packages/agent/src/ 下,文件名非常直白。

揭晓答案

packages/agent/src/agent-loop.ts

为什么重要:这是 agent 的心脏——"发消息给 LLM → 执行工具 → 再发"的循环。理解它,你就理解了"agent 到底是什么"。第 5 课会细读。

任务 3

找出"可运行的扩展示例"目录。
提示:里面应有 hello.ts、todo.ts、snake.ts、custom-provider-anthropic/ 等。

揭晓答案

packages/coding-agent/examples/extensions/

为什么重要:这是扩展能力的完整菜单,也是你的模板库。你想做的功能,八成在这里能找到模仿对象。其 README 值得通读一遍(今天先收藏,不着急)。

任务 4

找出"扩展开发文档"。
提示:在 packages/coding-agent/docs/ 下,文件名是 extensions 或 custom-provider 开头。

揭晓答案

packages/coding-agent/docs/extensions.md

为什么重要:这是扩展开发的权威文档,来自源码仓库(比 pi.dev 网站上的滞后版本更可信)。本课的推荐阅读就是它。

4 个都找到了?你已经会在这个仓库里"按图索骥"了——这就是开发者读陌生代码库的第一项技能。
